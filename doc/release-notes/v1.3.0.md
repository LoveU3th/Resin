# Resin v1.3.0

本版本合入上游 v1.2.0 / v1.3.0 的全部功能，并首次包含本 fork 的劣质节点池可用性优化。
This release merges upstream v1.2.0 / v1.3.0 and ships the poor-node-pool availability work
that previously only existed on this fork's master.

## Availability under poor node pools

- **Adaptive egress probing**: a node that has never sampled its egress IP is retried on a
  short backing-off interval (3m, doubling, capped at `max_egress_test_interval`) instead of
  waiting out the full refresh interval — one failed first probe no longer parks a node for
  a day. Half-open nodes without a sample are probed on the recovery spacing.
- **Staged probe accounting**: a probe failure that already saw the target answer through the
  node (positive latency, e.g. the target returned 502 or reset mid-body) only lowers the
  health score at the transfer weight and never feeds the circuit breaker. Unreachable nodes
  still trip the breaker at full weight.
- **Health-first candidate scan**: when both P2C picks are rejected by the health filter, the
  routable view is scanned (bounded at 64 candidates) so the acceptable minority is actually
  found in a pool where most nodes are failing. A fully healthy fleet pays nothing.
- **Connect-failure failover escalation**: while every failure so far is a connect-stage
  failure (the request provably never reached any upstream), the attempt cap widens by
  `failover_connect_extra_attempts` (default 2, new runtime setting). Any non-connect failure
  or the total budget stops the escalation.
- Sticky leases whose node failed to connect are rebound into the healthy pool; half-open
  probing has a minimum interval so dead nodes are not retried every scan.

## Inbound endpoint management (from upstream v1.2.0)

- Manage custom inbound endpoints from the WebUI or API.
- Configure admin console, HTTP forward/reverse, and SOCKS5 access per endpoint, with listener
  status and errors, plus enable/disable controls.
- CONNECT and WebSocket tunnels now close with their endpoint; hijacked connections are
  released on shutdown.
- With no `RESIN_PROXY_TOKEN`, endpoints can require Platform/Account identity for HTTP
  forward and SOCKS5; passwords are not validated.
- Endpoints reuse the same forward/reverse/SOCKS5 handlers, so health checks, failover, and
  sticky routing apply on every endpoint.

## Composable tag filter rules (from upstream v1.3.0)

- Platform tag filters are now composable: `Any` rules are ORed, `Must` rules are ANDed, and
  `MustNot` rejects. The previous single regex list migrates to `Must`, keeping the old
  AND semantics.

## Outbound and subscription fixes

- AnyTLS compatibility fixes and sing-anytls v0.0.13; AnyTLS client metadata disabled.
- QUIC TLS and VMess HTTP header corrections; HTTPS proxy nodes get distinct default tags.

## Observability

- Request log queries use composite indexes (ts+id, proxy_type+ts+id, account+ts+id) with an
  in-transaction index migration and cleanup of obsolete indexes.
- Dashboard trends are stabilized and incomplete buckets are marked; throughput curve
  optimized; lease account search added.
- Build version is derived from VCS by default.

## WebUI

- Administrator token field is masked with a visibility toggle; login page has a password
  show/hide field; layout fixes for long text, badges, and request logs.

## Upgrade Notes

> [!IMPORTANT]
> **`LEGACY_V0` has been removed.** An unset or empty `RESIN_AUTH_VERSION` defaults to `V1`;
> any other value prevents startup. If you run `LEGACY_V0`, switch to `V1` and update client
> credentials from `token:platform:account` to `platform.account:token`. See
> [doc/v1.0.0-migration-guide.md](../v1.0.0-migration-guide.md).

> [!IMPORTANT]
> **Persisted legacy Platform regex filters are automatically migrated to composable
> tag-filter rules during startup. This database migration is irreversible** because earlier
> releases cannot represent OR or exclusion rules.

- Back up `<RESIN_STATE_DIR>/state.db` before upgrading.
- To downgrade to an earlier release, stop Resin and restore the pre-upgrade backup. Do not
  attempt to roll back the migrated database.
- `state.db` migrates to schema version 9 (endpoints tables and the platform filter-rules
  column) automatically on first start; existing platforms, subscriptions, leases, and node
  state are preserved.
- New runtime setting `failover_connect_extra_attempts` (default 2) is backfilled
  automatically for configs persisted before it existed; set it to 0 to keep the flat
  attempt cap.
- The WebUI bundle is not tracked in git — rebuild it (`cd webui && npm install && npm run
  build`) before starting from source.
