# Resin v1.3.2

本版本修复「可路由视图里存在大批实际连不上的节点」：当一半节点连探测都无法应答时，
P2C 每次抽取都有很高概率落到死节点上，用户看到的是首跳失败、3 秒拨号超时后重试成功。
This release quarantines nodes that consecutive active probes cannot reach at all.

## 探测失败隔离

- 连续 3 次主动延迟探测都连不上节点（连接阶段失败）时，把该节点挂起 10 分钟，不参与
  选路；任一次探测成功立即解除。
- 挂起**不进熔断状态机**：`FailureCount` / `CircuitOpenSince` 不变，也不清空健康分，
  只是暂时不出现在候选里。与 P1-1 的零入向挂起同一套思路，信号源不同：零入向针对
  「连上了但不回数据」，本项针对「根本连不上」。
- 判定只用延迟探测（`LatencyTestURL` 返回 2xx），**不用出口探测**：出口探测读
  Cloudflare trace，该目标在部分网络下不可达。线上实测：110 个可路由节点里出口探测
  失败 61 个，随机串行复测 6 个，其中 3 个延迟探测正常。按出口探测挂起会误杀可用容量。
- 熔断拦不住这类节点的原因：熔断要求**连续** 3 次失败，而选点是随机的，失败会分散到
  整个池子，单个节点很难凑齐连续三次；一次成功又会把计数清零。隔离直接以探测结果为
  依据，与用户流量无关。

## 运行时配置

| 设置项 | 旧默认 | 新默认 | 说明 |
|---|---|---|---|
| `probe_quarantine_enabled` | 无 | true | 关闭后完全恢复旧行为，可热更新 |

阈值（3 次）与挂起时长（10 分钟）是代码常量，不开放配置：阈值取 1 会被探测目标自身
的抖动触发，取更大则死节点多服务一轮。需要调整时改 `internal/node/entry.go`。

## 兼容性

- `schema_version` 升到 4。旧配置在升级时**无条件**补成 `true`：bool 无法区分
  「字段缺失」与「显式关闭」，所以只能补一次；升级后显式设为 `false` 会持久保留。
- 回退旧版本二进制安全：读到 `schema_version=4` 会跳过迁移，未知 JSON 字段被忽略；
  本次没有任何 SQL migration。
- 无新增依赖，无协议变更。

## 验证

- 新增 5 个单测：阈值与到期、成功清零、路由拒绝与开关关闭、v4 迁移两个方向。
