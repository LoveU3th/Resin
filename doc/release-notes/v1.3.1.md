# Resin v1.3.1

本版本修复了 P2C 选点在真实流量下退化为「按租约数随机选择」的问题，并让劣质节点池
下的首跳质量真正参与决策。
This release fixes P2C selection degenerating into lease-count pick under real traffic,
and adds a targeted quarantine for nodes that blackhole CONNECT tunnels.

## 选点质量

- **延迟比较不再双双归零**：`compareLatencies` 在 target 域与探测 authority 都没有
  交集时，改为逐节点兜底（target 样本 → 该节点 authority 均值），而不是返回 `(0, 0)`。
  此前真实用户目标几乎必然走到这一步，于是评分只剩租约数，节点质量完全不参与。
- **未知延迟不再等于零延迟**：新增 `coldStartLatency = 400ms`，没有测量的节点不再
  以「零延迟」击败所有已测节点。`PreferIdleIP` 策略保持只按租约计分。
- **候选宽度自适应**：P2C 从固定 2 个候选改为按健康过滤可接受率调整
  （<35% 取 4，<60% 取 3，其余 2，上限 4），抽样上限 32 个候选；
  多候选用两两比较归约，复用原有三级延迟查找与评分路径。健康池行为不变。

## 零入向隧道挂起

- 节点接受 CONNECT、把客户端字节转发出去、然后一个字节都不返回，是劣质池中最常见的
  失败模式。这类请求无法重试（字节已写出，重放有重复提交风险），此前只能等熔断的
  连续失败计数攒够。
- 新增独立的零入向计数：连续 2 次即挂起 5 分钟，到期自动恢复。
- 挂起**不进熔断状态机**：`CircuitOpenSince` / `FailureCount` 都不修改，只是暂时不参与
  选点；任一条成功路径（流量或主动探测）都会立即清零。

## 运行时默认值

| 设置项 | 旧默认 | 新默认 | 说明 |
|---|---|---|---|
| `health_filter_threshold_percent` | 40 | 50 | 过滤线抬到 50% |
| `health_min_samples_for_filter` | 8 | 5 | 与 `health_ewma_min_samples` 对齐 |

已有部署的运行时配置是持久化的，升级后**不会**被新默认值覆盖；默认值只影响全新安装
和从未设置过的字段。

## 未包含

- `failover_total_budget` 保持 90s。降到更低会违反 `attempt_budget ≤ total_budget`，
  而 `attempt_budget` 不得短于 `ResponseHeaderTimeout`（默认 60s），否则慢但健康的
  上游会在回答前被放弃。
- 隧道流量暂不并入 `access-latency` 直方图：该直方图量程为 0–3s，而隧道首字节
  p99 约 3.6s，需要先调整量程参数，留待指标侧单独变更。

## 验证

- 新增 11 个单测（另有 1 个既有用例按新语义重写），覆盖单侧延迟保留、冷启动评分、
  宽度分段、挂起阈值/清零/到期、路由拒绝与上报路径。
- `go build ./...`、`go test ./...`、`go vet ./internal/...`、
  `go test -race ./internal/topology/ ./internal/routing/ ./internal/proxy/` 全部通过。
